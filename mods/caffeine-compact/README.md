# caffeine-compact

保活和"空闲时自动压缩"二合一。基于 [lperezmo/cache-caffeine](https://github.com/lperezmo/cache-caffeine)（MIT）改的，原有的保活、唤醒（wake）功能和命令都还在，新增了压缩和大小线。

## 安装

在 Claude Code 终端会话的输入框里：

```
/plugin install caffeine-compact --marketplace ckcyian23/claude-mods
```

提示添加市场时选 `y`，再选安装范围（一般选 user）。装好后重启 Claude Code（Desktop 也要重启）才会加载。

## 规则

保活由你手动开启，压缩是自动的，大小线（默认 200k tokens）只管自动压缩：

- **没开保活，上下文没到大小线**：不自动压缩，cache 过期就过期。
- **没开保活，上下文到了大小线**：在 prompt cache 过期前不久（1 小时 cache 提前 5 分钟，即最后一次请求后 55 分钟；5 分钟 cache 提前 1 分钟）自动压缩一次，只压一次。
- **开了保活**：不看大小线，每 55 分钟（1 小时 cache）戳一次。从你最后一次发消息算起满"保活时长"（默认 24 小时）后，如果你还没发新消息，就关掉保活；上下文到了大小线的话，再在 cache 过期前压缩。没到大小线就只关保活。

压缩要在 cache 还热的时候开始才划算，所以保活到时后不是立刻压，而是等到过期前不久。

**限额前提前压缩**（不管保活开没开）：5h 或周用量到 95%（未满 100%，可在配置菜单改），而且那个窗口的重置时间晚于 cache 的过期时间（上次请求加 1 小时），说明重置前 cache 一定会过期，重置后第一条消息要把整个上下文重写一遍（1 小时 cache 约 2 倍）。这时如果上下文到了 `limitsize`（默认 220k），就在当前回合结束后立刻压缩，不等 55 分钟。5h 和周额度各算各的，互不影响。重置早于 cache 过期时不压缩。

## 使用

- **离开前**：输入 `/caffeine` 开保活，或点状态栏的 `turn on`。`/caffeine` 只开不关，重复输入也还是开着。默认保活 24 小时（从你最后一条消息算起），到点自动关，不用管。
- **回来后**：直接发消息。保活想提前关，输入 `/caffeine off` 或点状态栏的 `turn off`。
- **不想保活**：什么都不用做。上下文到 200k 时，cache 过期前会自动压缩一次。
- **只要保活、不要自动压缩**：在配置菜单里关掉"自动压缩"，或输入 `/caffeine compact off`。过期前压缩和限额前提前压缩都不再做。
- **看状态**：`/caffeine status`。

## 配置菜单

在 `/plugin` 里找到 caffeine-compact，打开它的配置，下面这些都能直接改。对应的命令改的也是同一份设置，菜单里会同步显示：

| 设置 | 默认 | 说明 | 对应命令 |
| --- | --- | --- | --- |
| 自动压缩 | 开 | 关掉就只保活 | `/caffeine compact on\|off` |
| 自动压缩大小线（k tokens） | 200 | 上下文到这个值以上，没开保活时才会在 cache 过期前压缩 | `/caffeine size 300k` |
| 保活时长（小时） | 24 | 从你最后一条消息算起，这么久没发新消息就关保活，可写小数 | `/caffeine idle 2h` |
| 保活方式 | fork | fork 后台读缓存续命；prompt 每次发一条 poke 消息 | `/caffeine mode fork\|prompt` |
| 戳的间隔（分钟） | 0（自动） | 自动时 1 小时 cache 55 分钟、5 分钟 cache 4 分钟 | `/caffeine every 10m` |
| 状态栏显示 | auto | auto 有事才显示，on 一直显示，off 不显示 | `/caffeine band on` |
| 提示弹窗 | quiet | quiet 只弹失败、压缩完成、保活结束；normal 全弹 | `/caffeine notify normal` |
| 压缩提前量（分钟） | 5 | cache 过期前多少分钟开始压缩（1–30），5 分钟 cache 最多提前 1 分钟 | 只在菜单里 |
| 限额前提前压缩大小线（k tokens） | 220 | 见下面"限额前提前压缩" | `/caffeine limitsize 250k` |
| 限额前提前压缩触发线（%） | 95 | 5h 或周用量到这个百分比才考虑提前压缩（50–99） | 只在菜单里 |
| 状态栏提前显示（分钟） | 10 | 状态栏为 auto 时，压缩前多少分钟开始显示（0–60） | 只在菜单里 |

超出范围的值按默认值算。0.1.10 及以前用命令改过的设置，升级后会自动搬进配置菜单。

**全局设置和对话设置**：配置菜单和命令改的都是全局设置，所有对话（包括已经开着的）半分钟内跟着变。想让某个对话不一样，在命令末尾加 `here`，只改这个对话，优先于全局：

```
/caffeine size 300k here      这个对话的大小线单独设成 300k
/caffeine compact off here    这个对话只保活、不自动压缩
/caffeine size global         这个对话改回跟随全局
```

能单独设的有 `compact`、`size`、`limitsize`、`idle`、`every`、`mode`；状态栏、提示弹窗和三个阈值只有全局。`/caffeine status` 会列出这个对话单独设过的项。

### 状态栏（输入框上方那一行）

`/caffeine band auto|on|off`，也可以在 `/plugin` 的配置菜单里改默认值：

| 值 | 效果 |
| --- | --- |
| `auto`（默认） | 平时不显示。保活开着、压缩快到点（默认 10 分钟内）或正在压缩、正在改戳一下的话时才出现 |
| `on` | 一直显示 |
| `off` | 不显示；保活开着时信息改放在状态行 |

内容是 `cache 剩 38m  状态说明  turn on  message`。`t` 开关保活，`e` 改戳一下说的话。

## 命令

命令还是 `/caffeine`：

| 命令 | 作用 |
| --- | --- |
| `/caffeine compact on\|off` | 自动压缩开关（默认开） |
| `/caffeine compact now` | 立刻压缩一次，用来测试；结果或失败原因以提示显示 |
| `/caffeine compact skip` | 取消排好的这一次自动压缩（限额前提前压缩也一起取消），直到你发下一条消息。输入框上方压缩快到点时会出现 `skip compact` 按钮（快捷键 `x`），效果相同 |
| `/caffeine size 300k` | 大小线，低于它不自动压缩（不影响手动开的保活）（`default` 恢复 200k） |
| `/caffeine limitsize 250k` | 限额前提前压缩的大小线（`default` 恢复 220k） |
| `/caffeine idle 2h` | 保活时长：从你最后一条消息算起，到点关保活、转入压缩 |
| `/caffeine warm 2h` / `until 18:00` | 按绝对时间保活，到点同样转入压缩 |
| `/caffeine status` | 当前状态，含压缩计划和已压缩次数 |
| `/caffeine log [n]` / `log clear` | 看最近 n 条（默认 30）事件日志 / 清空；日志存在插件的存储里，最多留 300 条，重启后还在 |
| `/caffeine mode fork\|prompt` | 保活方式：`fork`（默认）在后台读主对话的缓存来续命，对话里没有 poke 消息，上下文不增长；`prompt` 发一条 poke 消息。fork 失败自动改发 poke |
| `/caffeine notify quiet\|normal` | 弹窗多少：`quiet`（默认）只弹失败、压缩完成、保活结束；`normal` 全弹。不管哪种，所有事件都写进日志。也在 `/plugin` 配置菜单里 |

其余命令（`on`、`off`、`every`、`ttl`、`wake` 等）见 `/caffeine help`。help 按用途分组（离开前/回来后、自动压缩、保活怎么做、限额唤醒、状态和提示、诊断），全部是中文。

## 说明

- `forever`（不设保活终点）不会转入压缩，因为保活一直开着。
- 普通的"cache 过期前压缩"在排了唤醒（wake）时不做，用量到 98% 时也不做（压缩本身要花几个百分点）。限额前提前压缩不受唤醒影响。
- 保活 poke 只在某个窗口用量到 100%（请求发不出去）时暂停，之前 90%/95% 的暂停线取消了：poke 很便宜（约一次重写的二十分之一），用量涨的时候不必停。
- **多账号**：缓存按组织、账号和模型分开。插件用会话自己的凭证向 Anthropic 查当前账号（只拿组织 ID 和账号 ID，插件看不到 token），Desktop 和 CLI 用不同账号、会话里 `/login` 换号都能认出来。每次成功的请求（以及保活 fork 读到热缓存）都按"组织 + 账号 + 对话 + 模型"记下时间，超过一天的自动清掉；压缩或 `/clear` 后给这个对话留一个"缓存已清空"的标记。
- **恢复会话**（进程重建、重新打开会话、切换账号后 Desktop 重启）时，只信记下的时间：
  - 当前账号和模型有记录：按记录接着算，保活和压缩照常。
  - 最后一次请求就是当前账号和模型：引擎报的"距上次回复多少秒"也算数。
  - 这个对话只在别的账号或模型上有记录，或者有压缩标记：当前账号上缓存是冷的，不保活、不压缩，等你发消息。
  - 什么记录都没有，或者查不到账号：时间不明。没开保活就什么都不做；开着保活（包括重启前开着的）就立刻 fork 一次来确认，热的话只花读缓存的钱，冷的话等于把缓存重新写一遍，之后保活照常进行，不会因此关掉。
  - 同一次回复被引擎重复报告时（间隔按整秒算，会差一点），几秒内的差别不算，倒计时不动。
- **保活开关跟着对话走**：按对话存进插件存储，进程重启后保持原样，之前开着就还开着，关着就还关着。关闭期间保活时长到了的，按到期处理。
- 请求失败（断网、登录失效，没有收到响应）不算续上了缓存，倒计时不会被它重置。
- cache 寿命（TTL）的判断：读到用量窗口说明是订阅，按 1 小时算，并记进插件存储，重启后的新进程也沿用。某次用量读数是空的（请求失败、断网、登录态被清掉、进程刚启动）时，沿用上一次读数得出的 TTL，不再当成 5 分钟。1 小时内第一次读不到缓存（切换账号、MCP 重连都会这样）只记为"冷了"，连续两次才改按 5 分钟。TTL 每次变化都会写进 `/caffeine log`，注明来源。
- 日志是所有会话共用的：每条都追加到存储里现有的内容后面，多个会话同时开着也不会互相覆盖。
- Desktop、`-p`、SDK 这类会话没有直接压缩的接口，插件会自动改成运行 `/compact` 命令来压缩，效果一样，但它是一个独立的回合，要等会话空闲才会执行。
- 压缩时给摘要加了说明，开头会写明这是自动压缩，并要求保留未完成任务、决定、文件路径等。
- 和原版 cache-caffeine、Compact On Idle、Idle Compact 不要同时装，会互相打架。
- 新增的提示文字是中文，原来的部分仍是英文。
